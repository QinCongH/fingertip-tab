## 1. 项目概述
“指尖乐谱”是一款基于 Rust 开发的本地化吉他谱桌面工具。它集成了吉他谱管理、多模式查看、AI 无接触交互等核心功能。项目致力于解决吉他手“找谱难、看谱累、翻页手忙脚乱”的痛点，提供高效、纯净的练琴体验。

## 2. 功能模块详解
### 2.1 模块一：吉他谱查看 (四种核心模式)
#### 模式 (1) 固定翻页看谱
*   **描述**：单页居中显示，支持点击或按键翻页。
*   **UI**：图片按屏幕比例适配，保持宽高比。
#### 模式 (2) 滚动看谱 (垂直)
*   **描述**：所有图片垂直拼接，适合浏览长篇曲谱。
*   **交互**：鼠标滚轮垂直滚动。
#### 模式 (3) 两张吉他谱水平对齐平铺滚动看谱
*   **描述**：图片两两并排，适配宽屏，支持水平滚动。
*   **对齐规则**：**严格按图片顺序对齐** (1&2一组，3&4一组)。
*   **适配**：高度铺满屏幕，宽度均分，最大化利用屏幕空间。
#### 模式 (4) AI 动作捕获翻页
*   **方案**：调用摄像头，识别用户**大幅度从左往右摇头**动作，触发“下一页”。
*   **技术**：使用 OpenCV 进行人脸追踪与位移计算。

#### 四大核心注意点实现方案

##### ① 支持自动滚动播放

- **需求描述**：解放双手，让谱子按一定速度自己移动。
- **实现逻辑**：
    - **触发机制**：在滚动模式（模式 2）和水平滚动模式（模式 3）下有效。
    - **速度控制**：
        - 提供一个滑动条，单位可以是“像素/秒”。
        - 或者是“BPM (每分钟节拍数)”，用户输入曲子速度，软件根据图片高度自动计算滚动速度。
    - **启停控制**：底部常驻一个“播放/暂停”按钮，支持空格键快捷切换。
    - **技术点 (Rust)**：使用 Tokio 的 `tokio::time::interval` 发送定时消息到前端 UI 线程，更新滚动容器的 `scrollTop` 或 `scrollLeft` 属性。

##### ② 支持吉他谱全屏查看

- **需求描述**：隐藏所有侧边栏、菜单栏、状态栏，沉浸式看谱。
- **实现逻辑**：
    - **全局快捷键**：`F11` 或 `Esc` 退出全屏。
    - **悬浮工具栏**：进入全屏后，所有常规 UI 消失。当鼠标移动到屏幕顶部/底部边缘时，浮现一个半透明的工具栏（包含：退出全屏、缩放、自动滚动开关）。
    - **技术点 (GUI)**：调用 Tauri/OS 的 Window API `set_fullscreen(true)`。

##### ③ 支持多张吉他谱时，两张水平对齐显示铺满全屏并支持滚动

- **需求描述**：这是对模式 (3) 的增强，强调“铺满全屏”的视觉体验。
- **实现逻辑**：
    - **CSS/Grid 布局**：
        - 外层容器：`display: flex; flex-direction: row; overflow-x: auto; height: 100vh;`
        - 内部单元：两张图片一组。`width: 50vw; height: 100%; object-fit: contain;`
    - **智能分组**：
        - 默认假设：`[0,1]` 为一组, `[2,3]` 为一组。
        - 如果用户只有 3 张图，第 3 张图是空白或只有一半内容，应居中显示或填充黑色背景。
    - **滚动行为**：
        - 鼠标滚轮在垂直滚动时，转换为水平滚动。
        - 或者使用触摸板水平滑动。

##### ④ 当用户选择支持捕获用户动作吉他谱翻页

- **需求描述**：即模式 (4) 的具体交互细节。
- **功能细化**：
    - **防误触**：设置“防抖动时间”，防止脚踏板连击导致一次翻了两页。
    - **反馈机制**：当接收到捕获信号并成功翻页时，屏幕边缘（或翻页区域）给出一个微弱的视觉闪烁或动画提示，确认操作已被执行（演出时很重要）。
    - **后台运行**：即便用户最小化了软件去开声卡软件，只要按下热键/脚踏板，软件窗口应自动弹起并置于前台（可选配置），或者在后台静默翻页。

### 2.2 模块二：录入吉他谱
此模块解决“数据从哪里来”的问题，需设计完善的文件处理与数据关联流程。
#### 1. 文件导入
*   **单张导入**：支持文件选择对话框导入图片。
*   **批量导入**：支持拖拽文件夹或多选文件，一键导入多张图片。
*   **截图录入**：提供屏幕截图工具，直接截取屏幕区域作为谱子。
#### 2. 存入方式设计 (核心设计)
为了防止文件名冲突、方便管理以及支持用户迁移，采用 **“元数据分离 + 文件重命名”** 的存储策略。
*   **步骤 1：文件存储与重命名**
    *   用户导入 `my-song.jpg`。
    *   系统生成一个唯一标识符（UUID），例如 `550e8400-e29b...`。
    *   系统将图片复制到用户指定的存储目录下的 `Resources/Images/` 文件夹。
    *   文件重命名为：`550e8400-e29b...jpg`。
    *   *目的*：即使多首歌叫同名图片，也不会冲突；用户删除原文件不影响库内文件。
*   **步骤 2：元数据录入**
    *   导入弹窗中，用户填写：歌名、艺术家、调式、BPM、标签。
    *   系统将上述信息与生成的 UUID 关联。
*   **步骤 3：图片预处理 (可选)**
    *   在保存前，提供旋转（90°/180°/270°）、裁剪功能。
    *   *注意*：预处理后的图片覆盖原 UUID 文件，不产生副本，保持库的整洁。
#### 3. 图片转文字 (OCR) (高阶功能)
*   集成 OCR 引擎（如 Tesseract），在导入时尝试提取图片中的文字，自动填充到歌名或备注栏，减少用户输入工作量。
#### 4. 分组归属设定

- **功能描述**：在导入吉他谱时，用户可以将谱子归档到一个或多个分组中。
- **交互设计**：
    - **导入弹窗**：在填写元数据的界面中，增加一个“所属分组”的多选下拉框或标签选择器。
    - **快速创建**：如果用户想要的分组不存在，支持在输入框内输入新名称并回车，实时创建新分组并选中。
    - **默认分组**：提供“未分类”或“全部曲谱”作为默认兜底选项。
- **逻辑**：
    - 用户导入 `Song A`。
    - 用户选择分组 `["指弹练习", "喜欢的歌"]`。
    - 保存后，`Song A` 同时出现在这两个分组的列表中。

### 2.3 模块三：数据存储
此模块是软件的基石，确保数据的安全、灵活与便携。
#### 1. 自定义存储目录
*   **初始化**：首次启动时，默认使用用户文档目录下的 `FingertipTabs` 作为存储库。
*   **设置修改**：用户可在“设置”中更改存储路径。
*   **目录结构设计**：
    ```text
    {User_Set_Path}/
    ├── FingertipTabs.db       (SQLite 数据库文件)
    ├── Resources/             (资源文件夹)
    │   ├── Images/            (存放所有图片)
    │   │   ├── {uuid1}.jpg
    │   │   └── {uuid2}.png
    │   └── Thumbnails/        (缓存缩略图，加速列表加载)
    │       └── {uuid1}_thumb.jpg
    └── Backups/               (自动备份目录)
    ```
#### 2. 数据库结构设计 (SQLite)
使用 SQLite 存储结构化元数据，保证查询效率。
**表：Songs (曲谱表)**
| 字段名 | 类型 | 描述 |
| :--- | :--- | :--- |
| `id` | INTEGER | 主键，自增 |
| `uuid` | TEXT | 唯一标识符，索引，对应文件名 |
| `title` | TEXT | 歌名 |
| `artist` | TEXT | 艺术家 |
| `album` | TEXT | 专辑 |
| `tuning` | TEXT | 调式 (如 Standard, Drop D) |
| `bpm` | INTEGER | 速度 |
| `file_type` | TEXT | 文件扩展名 |
| `created_at` | INTEGER | 创建时间戳 |
| `updated_at` | INTEGER | 更新时间戳 |


为了支持多对多关系（一首谱子可以属于多个分组，一个分组包含多首谱子），我们需要引入关联表。

**表：Collections (分组表)**

|字段名|类型|描述|
|---|---|---|
|`id`|INTEGER|主键，自增|
|`name`|TEXT|分组名称 (如 “演出歌单”, “五月天”)|
|`created_at`|INTEGER|创建时间戳|

**表：Songs (曲谱表)**

|字段名|类型|描述|
|---|---|---|
|…|…|… (保持原有字段不变)|

**表：Song_Collections (谱子-分组关联表)**

|字段名|类型|描述|
|---|---|---|
|`id`|INTEGER|主键|
|`song_id`|INTEGER|外键，关联 `Songs.id`|
|`collection_id`|INTEGER|外键，关联 `Collections.id`|

- *设计说明*：使用关联表可以避免在 `Songs` 表中存储冗余的分组字段（如 `group1, group2...`），也方便未来扩展（例如给分组加颜色、图标）。
#### 3. 数据迁移功能
*   **场景**：用户想将谱子库从 C 盘移动到 D 盘。
*   **逻辑**：
    1.  用户在设置中选择新路径。
    2.  软件检查新路径是否为空。
    3.  **物理移动**：将 `Resources` 文件夹和 `.db` 文件移动到新路径。
    4.  **更新配置**：更新本地配置文件中的路径指向。
    5.  **原子性**：如果移动中断（如断电），需保留原数据，避免数据丢失。
#### 4. 备份与恢复
*   **备份**：提供“一键备份”功能，将整个库目录打包成 ZIP 文件。
*   **恢复**：支持读取 ZIP 包，解压并覆盖当前库，实现数据回滚。

#### 4. 交互与逻辑细节
1.  **即时生效 vs 重启生效**：
    *   大部分设置（如主题、灵敏度、快捷键）应支持**即时生效**，无需重启软件。
    *   **存储路径修改**属于高危操作，修改后需要提示用户“正在迁移数据...”，迁移完成后建议重启应用以确保所有路径句柄更新。
2.  **重置默认**：
    *   在设置页面底部提供“恢复默认设置”按钮。
    *   点击后弹出警告：“这将清除你的所有个性化配置（不会删除曲谱文件），确定吗？”
3.  **配置校验**：
    *   如果用户设置了不合法的路径（如只读盘），软件应在启动时检测并回退到默认路径，同时弹窗提示用户。

## 3. 技术实现补充 (针对录入与存储)
### Rust 技术栈更新
*   **文件 IO**：`std::fs` (用于文件复制、移动、目录创建)。
*   **UUID 生成**：`uuid` crate，用于生成唯一的文件名。
*   **数据库**：`sqlx` (SQLite)，用于执行 CRUD 和事务操作。
*   **路径处理**：`dirs` crate，用于获取系统默认文档目录。
*   **OCR**：`tesseract-rs` (可选)，用于文字识别。
### 数据流逻辑示例 (导入流程)
```rust
pub async fn import_song(file_path: PathBuf, meta: SongMeta, db: &SqlitePool) -> Result<()> {
    // 1. 生成 UUID
    let uuid = Uuid::new_v4().to_string();
    
    // 2. 确定目标存储路径
    let storage_dir = get_storage_dir().await?; // 从配置读取
    let dest_dir = storage_dir.join("Resources/Images");
    let extension = file_path.extension().unwrap().to_str().unwrap();
    let dest_filename = format!("{}.{}", uuid, extension);
    let dest_path = dest_dir.join(&dest_filename);
    // 3. 复制文件
    tokio::fs::copy(file_path, &dest_path).await?;
    // 4. 写入数据库
    sqlx::query!(
        r#"INSERT INTO songs (uuid, title, artist, file_type) VALUES (?, ?, ?, ?)"#,
        uuid,
        meta.title,
        meta.artist,
        extension
    )
    .execute(db)
    .await?;
    Ok(())
}
```

## 4. 非功能性需求
1.  **数据一致性**：在文件复制和数据库写入之间，必须使用事务或原子操作。如果文件复制失败，不能插入数据库记录。
2.  **性能**：
    *   列表加载时优先显示缩略图，懒加载原图。
