
# 📄 指尖乐谱 - 功能迭代需求文档
## 一、概述
本次迭代围绕三个目标展开：
1. **大屏自适配模式**：让主界面、看谱页在不同分辨率下都能充分利用屏幕空间，尤其优化横屏大屏场景。
2. **局域网共享预览模式**：通过内嵌 HTTP 服务，允许手机、平板或其他电脑通过浏览器访问同一局域网内主机的曲谱进行查看，无需安装客户端。
3. **曲谱列表分页**：当曲谱数量增长到上百首时，列表支持分页加载，避免一次渲染全部数据导致的卡顿。
**不变的基石**：`Songs` 表结构、`Resources/Images` 与 `Resources/GPFiles` 目录的物理存储逻辑、图片/GP 双模式的查看分流逻辑均保持现状，本次迭代只做"增量扩展"。
---
## 二、模块一：曲谱列表分页
### 2.1 后端接口设计（Tauri Commands）
| 命令名 | 参数 | 返回 | 说明 |
| :--- | :--- | :--- | :--- |
| `get_songs_paged` | `page: i32`, `page_size: i32`, `group_id: Option<i32>`, `keyword: Option<String>` | `{ items: Vec<Song>, total: i64, page: i32, page_size: i32 }` | 按条件分页查询 |
| `get_songs_count` | 同上（筛选条件） | `i64` | 用于计算总页数 |
**核心 SQL（LIMIT/OFFSET 模式）**：
```sql
-- 数据查询
SELECT * FROM songs
WHERE (?group_id IS NULL OR group_id = ?group_id)
  AND (?keyword IS NULL OR title LIKE '%' || ?keyword || '%')
ORDER BY created_at DESC
LIMIT ?page_size OFFSET ?offset;
-- 总数查询（用于分页条）
SELECT COUNT(*) FROM songs WHERE ...同上筛选条件...;
```
**OFFSET 计算公式**：`offset = (page - 1) * page_size`，页码从 1 开始。
**参数约束**：
- `page_size` 可选值：`20 / 50 / 100`（前端下拉）。
- 若 `page` 超出总页数，自动返回最后一页数据。
### 2.2 前端实现（Vuetify 分页组件）
`src/views/Library.vue` 调整：
- **数据加载**：替换原"一次性拉全量"的写法，改为 `watch([page, pageSize, keyword])` 触发重新调用 `get_songs_paged`。
- **分页条**：使用 `<v-pagination>` 组件，绑定 `page` 状态。
- **页大小选择**：使用 `<v-select>`，选项 `[20, 50, 100]`。
- **排序与筛选联动**：分组切换、关键词搜索时强制重置 `page = 1`。
- **加载态**：使用 `<v-overlay>` 显示加载遮罩，防止用户连续点击造成请求风暴。
**交互细节**：
- 切换页时保留滚动位置可选（"记住位置"开关）。
- 删除曲谱后自动重新请求当前页，若当前页已空则回退一页。

## 三、模块二：大屏自适配模式
### 3.1 断点策略（基于 Vuetify useDisplay）
Vuetify 默认断点：`xs<600 / sm<960 / md<1280 / lg<1920 / xl≥1920 / xxl≥2560`。结合"看谱"场景，自定义如下策略：
| 断点 | 典型设备 | 布局策略 |
| :--- | :--- | :--- |
| `xs / sm` | 手机、竖屏平板 | 侧边栏折叠为抽屉，单列卡片，底部悬浮翻页按钮 |
| `md` | 平板横屏 | 侧边栏可折叠，双列卡片 |
| `lg / xl` | 笔记本、桌面 | 侧边栏常驻，三列卡片，谱面居中展示 |
| `xl / xxl`（≥1920） | **大屏/演出屏** | 启用"大屏模式"：隐藏侧边栏，谱面最大化，工具栏半透明悬浮，底部大按钮 |
### 3.2 看谱页大屏适配
- **谱面区域**：通过 `useDisplay()` 响应式读取 `width/height`，动态设置 `<v-container>` 的 `max-width` 与 `padding`。
- **双页模式**：在 `lg` 及以上断点，默认启用"双页水平"看图模式；`md` 以下回退单页。
- **大字号控件**：`xl` 断点下，翻页按钮、播放控制按钮的 `size` 从默认切换为 `x-large`，方便台下走动时操作。
- **全屏沉浸**：提供"演出模式"开关（设置项），开启后：
  - 隐藏顶栏、侧边栏；
  - 鼠标静止 3 秒后自动隐藏所有 UI，移动鼠标唤出；
  - 快捷键：`F11` 进入/退出全屏。
### 3.3 设置项新增
在 `settings.json` 的 `display` 节新增：
```json
{
  "display": {
    "stage_mode": false,          // 演出模式（沉浸式大屏）
    "auto_hide_toolbar": true,    // 大屏下鼠标静止自动隐藏工具栏
    "dual_page_threshold": 1280,  // 启用双页模式的最小宽度
    "button_size_on_large": "x-large"
  }
}
```
### 3.4 实现要点
- 使用 Vuetify 的 `useDisplay()` composable，监听 `width/height/name` 响应式变化，不要手写 `window.resize` 监听。
- 演出模式的 UI 隐藏逻辑封装为 `useStageMode()` composable，供 `Home.vue` 和 `GpViewer.vue` 复用。

## 四、模块三：局域网共享预览模式
### 4.1 功能定位
主机端（"指尖乐谱"桌面应用）在内嵌一个轻量 HTTP 服务，同一 Wi-Fi/局域网下的手机、平板可通过浏览器访问指定地址，浏览并查看曲谱（图片可直接预览；GP 谱以图片快照形式预览，播放功能保留在主机端）。
**明确边界**：
- ✅ 访客端：浏览曲谱列表、查看图片谱、查看 GP 谱的静态渲染图。
- ❌ 访客端：不支持 GP 实时播放（避免重复引入 AlphaTab 音色库带来的移动端负担）、不支持上传/修改/删除。
### 4.2 技术选型
| 层级 | 选型 | 说明 |
| :--- | :--- | :--- |
| HTTP 服务 | **axum** (Rust) | Tauri 生态最主流的轻量 Web 框架，与现有 tokio 运行时无缝集成 |
| 静态资源 | `tower-http::ServeDir` | 用于托管访客端 H5 页面 |
| 数据交互 | JSON API | `/api/songs` 等只读接口 |
| 鉴权 | 可选 PIN 码 | 简单 4-6 位数字，避免局域网内被陌生人浏览 |
### 4.3 后端接口设计
| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| `GET` | `/api/songs?page=1&size=20` | 分页获取曲谱列表（不含敏感字段如本地路径） |
| `GET` | `/api/songs/:id` | 获取单首曲谱元数据 |
| `GET` | `/api/songs/:id/image/:page` | 流式返回图片谱某页（支持 Range） |
| `GET` | `/api/songs/:id/preview` | GP 谱预渲染的 PNG 快照（首次访问时由主机生成并缓存） |
| `GET` | `/api/qrcode` | 返回访问二维码（或由前端生成） |
**安全要点**：
- 所有接口只读，不暴露文件系统绝对路径。
- 服务仅监听 `0.0.0.0` 但提供开关，可设置为仅 `127.0.0.1`（关闭共享）。
- PIN 码通过 Query 参数或 Header 校验，错误重试 5 次后锁定 60 秒。
### 4.4 服务生命周期
- **启动/停止**：设置面板提供开关，默认关闭。开启后由 Rust 端 `tokio::spawn` 启动 `axum::Server`，绑定可配置端口（默认 `7788`）。
- **地址展示**：UI 上显示"访问地址：`http://192.168.x.x:7788`"+ 二维码，方便手机扫码。
- **应用退出**：主进程退出时优雅关闭 HTTP 服务（使用 `CancellationToken`）。
### 4.5 前端设置面板新增
在"设置 → 共享"页签下：
```
[ v-switch ] 启用局域网共享预览
[ v-text-field ] 端口号 (默认 7788)
[ v-text-field ] 访问 PIN 码 (可选, 4-6位)
[ v-btn ] 生成二维码 (弹出 <v-dialog> 展示二维码)
当前状态: ● 运行中  http://192.168.1.100:7788
```
### 4.6 访客端 H5 页面
独立于主 Vue 应用，构建产物放置于 `src-tauri/static/guest/`，由 `ServeDir` 托管。
- 简化版曲谱列表（分页加载）。
- 点击谱子 → 查看大图（图片谱翻页、GP 谱显示预渲染 PNG）。
- 响应式适配手机竖屏，深色主题默认。
- 顶部显示"由 指尖乐谱 主机共享 · 只读模式"。
### 4.7 GP 谱预渲染策略
由于 GP 谱无法在手机浏览器直接播放，方案如下：
1. 用户在主机端首次打开某 GP 谱时，AlphaTab 已渲染出 SVG/Canvas。
2. 后台触发"导出为长图"逻辑（AlphaTab 支持），保存到 `Resources/Previews/{song_id}.png`。
3. 访客端通过 `/api/songs/:id/preview` 获取该 PNG。
4. 若尚未生成，主机在收到该请求时同步生成一次并缓存。

## 七、关键风险与注意事项
1. **端口冲突**：启动共享服务前需检测 `7788` 端口是否被占用，占用则提示用户更换端口。
2. **防火墙**：Windows 首次启动 HTTP 服务会触发防火墙弹窗，需在 UI 提前说明"允许访问"。
3. **大图片性能**：访客端请求图片时，建议后端做缩略图缓存（原图保留），避免手机加载 5MB+ 的高清谱面。
4. **二维码生成**：可在前端使用 `qrcode` npm 包直接生成，无需后端参与。
5. **GP 预览图生成耗时**：首次生成可能需要 2-5 秒，应在访客端显示"生成中"占位符。

# 指尖乐谱 - 多图自适应布局（大屏看谱模式）
## 一、布局规则定义
根据曲谱的图片数量 `N`，自动匹配最佳布局（基于 CSS Grid 实现）：
| 图片数 | 布局结构 | Grid 定义 | 示意图 |
| :--- | :--- | :--- | :--- |
| **1 张** | 单图居中 | `grid-template-columns: 1fr` | 图铺满或按比例居中 |
| **2 张** | 左右均分 | `grid-template-columns: 1fr 1fr` | 图1 \| 图2 |
| **3 张** | 左大右二叠 | `1fr 1fr` + 左侧跨2行 | 图1（大）\| 图2 / 图3 |
| **4 张** | 田字四等分 | `1fr 1fr` + `1fr 1fr` | 图1 图2 / 图3 图4 |
| **> 4 张** | 分组翻页 | 每屏 4 张，按田字布局分页展示 | 第1屏4张 → 第2屏4张... |
**设计要点**：
- 使用 `grid-template-areas` 命名区域，布局切换只需改变一个 CSS 类，无需操作 DOM 顺序。
- 图片统一使用 `object-fit: contain`，保证谱面不裁切、不变形。
- 格子之间留 `gap: 8px` 间隙（可配置为 0，实现无缝拼接长谱）。

## 二、核心组件实现
### 2.1 布局计算逻辑
新建 `src/composables/useGridLayout.ts`：
```typescript
import { computed } from 'vue'
export type LayoutClass = 'layout-1' | 'layout-2' | 'layout-3' | 'layout-4'
export function useGridLayout(imageCount: () => number) {
  // 根据图片数量返回布局类名
  const layoutClass = computed<LayoutClass>(() => {
    const n = imageCount()
    if (n <= 1) return 'layout-1'
    if (n === 2) return 'layout-2'
    if (n === 3) return 'layout-3'
    return 'layout-4' // 4张及以上（超出部分翻页）
  })
  // 当前屏应显示的图片切片（支持 >4 张时分页）
  const pageImages = (images: string[], page: number, perScreen = 4) => {
    const start = (page - 1) * perScreen
    return images.slice(start, start + perScreen)
  }
  const totalPages = (total: number, perScreen = 4) =>
    Math.ceil(total / perScreen)
  return { layoutClass, pageImages, totalPages }
}
```

### 2.3 在查看页集成（配合翻页）
修改 `src/components/ImageViewer.vue`，将原来"单张图片显示"替换为多图布局：
```vue
<template>
  <div class="viewer-wrapper fill-height">
    <!-- 多图自适应布局 -->
    <MultiImageLayout
      :images="currentPageImages"
      @select="onImageSelect"
    />
    <!-- 多屏翻页控制（>4张时出现） -->
    <div v-if="totalScreenPages > 1" class="screen-pager">
      <v-btn icon="mdi-chevron-left" @click="prevScreen" :disabled="screenPage <= 1" />
      <span class="mx-4">{{ screenPage }} / {{ totalScreenPages }}</span>
      <v-btn icon="mdi-chevron-right" @click="nextScreen" :disabled="screenPage >= totalScreenPages" />
    </div>
  </div>
</template>
<script setup lang="ts">
import { ref, computed } from 'vue'
import MultiImageLayout from '@/components/MultiImageLayout.vue'
import { useGridLayout } from '@/composables/useGridLayout'
const props = defineProps<{ images: SongImage[] }>()
const PER_SCREEN = 4
const screenPage = ref(1)
const totalScreenPages = computed(() =>
  Math.ceil(props.images.length / PER_SCREEN)
)
// 当前屏展示的 4 张（或更少）图片
const currentPageImages = computed(() => {
  const start = (screenPage.value - 1) * PER_SCREEN
  return props.images.slice(start, start + PER_SCREEN)
})
const nextScreen = () => screenPage.value++
const prevScreen = () => screenPage.value--
// 支持键盘翻屏
const onKeydown = (e: KeyboardEvent) => {
  if (e.key === 'ArrowRight' || e.key === 'PageDown') nextScreen()
  if (e.key === 'ArrowLeft' || e.key === 'PageUp') prevScreen()
}
window.addEventListener('keydown', onKeydown)
</script>
```

## 四、与已有功能的联动
### 4.1 与“大屏演出模式”联动
- 演出模式下（`stage_mode: true`），`gap` 自动归零、`padding` 归零，实现 4 张谱面**无缝满屏**铺满。
- 鼠标静止 3 秒隐藏翻页按钮，快捷键翻页。
### 4.2 与“设置”联动
在 `settings.json` 的 `display` 节新增配置项：
```json
{
  "display": {
    "multi_image": {
      "gap": 8,               // 格子间距，0 为无缝
      "background": "#1e1e1e", // 格子底色
      "per_screen": 4,         // 每屏图片数（预留，未来可支持6格）
      "fit_mode": "contain"    // contain(完整) | cover(铺满，会裁切)
    }
  }
}
```
### 4.3 与“局域网共享预览”联动
访客端 H5 页面直接复用同一套 Grid 布局的 CSS（将样式抽离为独立文件 `grid-layout.css`，两端共用），保证手机/平板上看到与主机一致的排列效果。
### 4.4 与翻页手势联动
- 触屏设备：左右滑动 = 翻屏（配合 `@touchstart/@touchend` 手势识别）。
- 蓝牙踏板翻页器：映射为 `ArrowLeft/ArrowRight` 键盘事件，天然兼容。

**关键技术提示**：
1. 3 张图的布局**必须用 `grid-template-areas`**，而不是简单的 `flex` 嵌套——这样图1跨两行的语义最清晰，且切换布局时只需改类名，无 DOM 重排。
2. 图片 `object-fit: contain` 是底线，吉他谱任何裁切都是不可接受的。
3. `convertFileSrc()` 是 Tauri 提供的将本地路径转为 `asset://` 协议的方法，需在 `tauri.conf.json` 中开启 `assetProtocol` 并配置允许目录为 `Resources/Images`。
这样，大屏看谱模式就具备了“1居中 / 2对开 / 3主次 / 4宫格”的完整自适应能力。
